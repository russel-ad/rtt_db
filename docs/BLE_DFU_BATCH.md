# BLE DFU 多设备批量升级

在原有“蓝牙 DFU 升级”页扩展，保留 RTT / 串口调试及单设备连接查询。
本次修改仅位于 `G:\rtt_db`，不修改从机固件工程。

## 使用

1. 启动 `rtt_t2_ble_dfu_batch.exe`，切换“蓝牙 DFU 升级”。
2. 检查蓝牙、扫描设备，然后在设备名称前勾选需要升级的设备。可以筛选后勾选可见设备；筛选不会清除已隐藏设备的勾选，“清空勾选”会全部清除。重新扫描会移除未再次发现的设备。
3. 选择 OnMicro APP-only DFU ZIP，核对目标版本和设备分区。同一批使用同一个 ZIP、分区选项及目标版本。
4. 保持“批量升级”勾选，设置“同时升级”：默认 2 台，可选 1～4 台。1 台表示排队逐台升级，2～4 台表示并行上限，实际能力取决于电脑蓝牙适配器及无线环境。
5. 点击“开始批量升级”。工具依次取出勾选设备，自动连接、查询 ROM/布局/版本、传输、校验提交、等待重启并确认目标版本。无需提前手动连接每一台。
6. 观察每台设备的阶段、传输百分比、速度、版本及结果。结束后可导出 CSV 结果或日志。

取消勾选“批量升级”即可使用原来的单设备连接、查询、升级流程。
扫描列表新增“RSSI 过滤”，勾选后可设置最低信号门限（-127～0 dBm，初始值 -70 dBm）。只显示 RSSI 大于或等于门限的设备，例如 -70 dBm 会保留 -60 dBm、隐藏 -80 dBm；与名称/地址筛选同时生效，修改门限立即更新本次扫描列表，无需重新扫描。默认不启用 RSSI 过滤。筛选隐藏的已勾选设备仍属于本批，界面会显示隐藏勾选数量；需要移除时点击“清空勾选”，再勾选可见设备。
默认首次升级上限 280 KiB；只有同批设备均已确认完成分区迁移，才选择 400 KiB。
手机应先释放连接，从机也需处于允许电脑连接的状态；工具不自动清配对或恢复出厂设置。

## 结果与停止

- 同一蓝牙地址在一批中只处理一次；一台失败不取消其他设备。失败、同版本拒绝或结果待确认的设备不会自动重试。
- 传输 100% 仍需等待提交、重启和版本确认，不能直接判定成功。
- “停止批量”取消排队、连接中及提交前的传输；已进入最终提交的设备继续完成重启和版本确认。界面会显示等待状态，不能保证立即结束所有连接。
- 关闭窗口时采用同样的停止策略，待任务结束并断开连接后关闭。
- 最终提交回执丢失或提交后版本未确认，显示“结果待确认”，应先查询设备版本，不自动重发 Execute。
- 每台设备独立使用协议状态、通知队列和连接监视；并发上限覆盖连接、升级、版本确认和连接清理的整个生命周期。
- 传输日志标记设备地址；总日志保存在 `%LOCALAPPDATA%\RTT_T2\ble_dfu\logs`。
- 批量使用同一份 BIN 的 SHA-256 作为基准，每台写入前重新加载并校验包；中途替换包会阻止后续设备使用不同 BIN。
- 连接复用本次扫描得到的原生 BLE 对象，避免仅传地址时各连接触发隐式扫描。

## 效率验证

并发不承诺按设备数量倍增速度。建议用同一批设备和同一包，分别测量并发 1、2 时的整批耗时及成功率，再评估 3、4。
本次交付只做离线模拟、原生 Windows UI 和本机适配器检查，没有扫描或升级真实设备，不能替代实机并发吞吐和可靠性验证。
