# SC201 host implementation history

Historical local build paths are retained for traceability. Current downloads and source instructions are in [README](../README.md).

## SC201 工作台 RSSI 过滤（v2.9.5）

左侧“扫描／连接设备”下方增加 RSSI 过滤开关和阈值，默认 **≥ −60 dBm**，设置自动保存。扫描信号更新后即时调整列表，隐藏项自动取消批量勾选。下载[新版便携 ZIP](../dist/sc201_workbench_portable_batch_ota_rssi_20261103.zip)，完整解压后运行文件夹内 EXE；操作见[工作台说明](SC201_WORKBENCH.md)。

## SC201 双台240秒目标：本机实测205.77秒（2026-11-03）

已完成设备端OTA连接协商和存储调度优化，并使用现有v2.9.4上位机验收：05FFE9、047FF6并发升级同一份715076字节镜像，从点击开始到两台重启、重新认证并验版成功，总计205.770秒。纯数据157.894／160.640秒，零块重传；两次OS观察均为7.5 ms连接间隔、双向2M PHY。本机本轮满足≤240秒，其他电脑和射频环境仍需验证。

这次需更新设备端固件，现有v2.9.4上位机继续使用；首次部署由旧固件接收，之后才使用新接收逻辑。使用[已验收固件包](../dist/sc201_ota240_verified_20261103.zip)，设置并发2台、确认后立即推进开、缩块和吞吐优先关。目标为SC200-D／DFT-SC20X-HUB／V001_006；操作及现场记录见[多设备固件升级](SC201_BATCH_OTA.md)。此前便携程序与候选包均保留。

## SC201 多设备升级事件推进与计时（v2.9.4，设备端优化前）

新增“确认后立即推进”：在同一通信线程内继续执行已就绪的 OTA 状态，减少等下一次 10 ms 轮询的空档；每次最多 8 步，等待回执或连接代次改变时停止。保留逐块 ACK、存储确认、CRC、重启及验版流程。新增每块“排队到 ACK”“排队到存储报告”“全部确认到下一块排队”的分段累计计时；仅输出数值，不输出协议正文或凭据。

便携包：`dist/sc201_workbench_portable_batch_ota_event_20261102.zip`。默认开启“确认后立即推进”，保留 216 字节原分块，两个蓝牙调优选项继续默认关闭。2026-11-03 授权实机对照中，两台分别传输 430.451 / 462.148 秒，均重启验版成功；确认后下一块排队仅约 0.03 ms，但总耗时没有改善，未达到双台 220 秒。主要等待仍在匹配 ACK 和存储报告到达之前。现场报告单独保存，原 ZIP 保持不变；实现与计时边界见 [多设备固件升级](SC201_BATCH_OTA.md)。

## 历史 v2.9.3 默认设置修正

已实时读取上位机并完成同两台 SC200-D、同一份 V001_006 镜像的授权对照升级。v2.9.2 两个调优选项开启时，纯数据传输为 515.493 / 513.390 秒；两个选项关闭、恢复 216 字节块后为 417.689 / 432.335 秒，两台均重启、重新认证并验版成功。小块方案在本机反而更慢，因此 v2.9.3 将“按蓝牙 MTU 缩小固件块”和“吞吐优先（Windows 11）”默认关闭，保留日志过滤、耗时诊断和界面刷新改进。两个选项仍可手动选择。

便携包为 `dist/sc201_workbench_portable_batch_ota_baseline_20261102.zip`，完整解压后运行文件夹内 EXE。该版本修正已测出的减速设置；双台仍约 7 分钟，尚未达到单台约 220 秒的耗时。实际连接间隔仍为 30 ms，主要等待发生在 Windows 写入提交之后的无线传输和协议回执阶段，尚未区分其中各段的占比。数据、计时口径与验证范围见 [多设备固件升级](SC201_BATCH_OTA.md)。

## 历史 v2.9.2 分块方案（实机已确认减速）

根据 v2.9.1 的实机日志继续优化：Windows 吞吐请求被接受，但实际连接间隔仍为 30 ms，双台完整传输约 462 / 473 秒。新增“按蓝牙 MTU 优化固件块”，默认开启；在 ATT 244、明文容量 236 时使用 176 字节固件块，加密帧最多 243 字节，一次蓝牙写入可装下。原 216 字节块需要两次写入。小 MTU 或关闭选项时保留原分块，并新增 Windows 写入完成及 Qt 调度的耗时汇总日志。

历史便携包：`dist/sc201_workbench_portable_batch_ota_mtu_20261102.zip`。现场实测没有得到预期提速；请使用上方修正版或在旧版中关闭两个调优选项。减少写入次数不能等同于无线耗时同比下降。

## 历史 v2.9.1 吞吐请求与日志优化

批量升级默认开启“吞吐优先（Windows 11）”，传输期间请求系统吞吐参数，重启或取消后释放；不支持时沿用系统设置。修复批量地址前缀使详细日志过滤失效的问题，日常升级关闭“详细日志”可省去逐包十六进制展开和逐块日志。结果表每 250 ms 刷新，分别记录传输与总耗时；真实无线速率仍取决于适配器、Windows 和设备。

新版便携包：`dist/sc201_workbench_portable_batch_ota_fast_20261102.zip`。完整解压后运行文件夹内 EXE，保留 `_internal` 和所有 DLL；操作和复测步骤见 [多设备固件升级](SC201_BATCH_OTA.md)。

## SC201 多设备固件升级（v2.9.0）

在“SC201 设备工作台 → 固件升级”勾选左侧多台设备，设置同时升级 1～4 台（默认 2 台）。每台独立连接、App3 认证、加密传输、重启及验版，支持单台/全部取消、失败重试和 CSV 结果导出。需要绑定的设备单独提示，由操作者打开绑定窗口后继续。

分发包为 `dist/sc201_workbench_portable_batch_ota_20261102.zip`，完整解压后运行其中 EXE；保留 `_internal` 和全部 DLL。操作与验证说明见 [多设备固件升级](SC201_BATCH_OTA.md)。

分发到其他电脑，使用 `dist/sc201_workbench_portable_20261102.zip`：完整解压，保留所有文件和 `_internal`，运行文件夹内的 EXE。此版本无需启动时向系统临时目录解压依赖，可避开原单文件包的 `Could not create temporary directory!` 报错；详见 [便携版启动说明](PORTABLE_START.md)。

原单文件版为 `dist/sc201_workbench_integrated_20261102/rtt_t2_sc201_workbench_integrated_20261102.exe`。工作台顶部显示实际资料目录，开发机优先沿用来源工程资料；原独立工作台应先正常关闭，避免同时使用同一份台账。操作、构建和验证范围见 [SC201 工作台集成说明](SC201_WORKBENCH.md)。

## BLE 出厂配对（2026-10-24 新增）

新增“出厂配对”页：通过 BLE 连接 SC200-D 主机，查询主机及当前磁吸/在线秤的 SN、MAC、型号，选择单秤或双秤 Top/Bottom，保存两端出厂配对并回读。独立返工入口用于替换已有套装；主从完整断电重开后可做纯 BLE 复验并导出报告。不会修改设备自身 SN。

需使用本次支持 BLE `factory.pair` 的主机固件，配套秤沿用已有固化协议。具体步骤、流程图、失败处理和构建命令见 [BLE 出厂配对操作说明](BLE_FACTORY_PAIR.md)。普通保存成功报告 `qualified=false`，断电后复验成功才是 `qualified=true`。本次仅完成离线验证，未对现场设备固化或烧录。

## 蓝牙 DFU 升级界面（2026-10-22 新增）

上位机保留 RTT / 串口调试与资源文件发送，增加 OnMicro BLE DFU：设备扫描、名称/地址及 RSSI 筛选、ZIP 校验、单设备或多设备升级、重启后目标版本确认。批量默认并发 2 台，可设置 1～4 台；1 台为逐台升级。

分区支持从机 0x404000 的 280/400 KiB，以及主机 SC200-D / DFT-SC20X-HUB 的不断电 OTA 752 KiB（0x409000）。主机使用独立 DAT/尾部格式，允许升计数、同计数重装及降计数，并在重启后核对版本、APP长度和计数；显示版本相同时仍需勾选“允许重装同版本”。旧设备固件自身可能仍限制降级。最新EXE路径和步骤见[主机升降级说明](HOST_OTA_ROLLBACK_20261023.md)。

总进度、速度和停止按钮固定在页面底部，每台设备独立显示进度条、阶段和结果。开始升级后自动收起设置区，可随时展开。操作说明见 [批量升级](BLE_DFU_BATCH.md)、[RSSI 筛选](BLE_DFU_RSSI_20261022.md)及[进度显示修复](BLE_DFU_PROGRESS_FIX_20261022.md)。

在原有主程序依赖基础上安装 BLE 依赖，运行或打包最新版：

```powershell
python -m pip install -r requirements_ble_dfu.txt
python rtt_ble_launcher.py
python -m unittest discover -s tests_ble_dfu -q
.\build_ble_dfu.ps1 -HostScale -Suffix portable
```

EXE 输出到 `dist/ble_dfu_host_scale_portable/rtt_t2_ble_dfu_host_scale_rssi_portable.exe`。BLE OTA / 串口运行不要求安装 J-Link 软件包；原生 J-Link DLL 延迟到点击 RTT 连接时加载，缺少组件时显示明确提示。详见 [J-Link DLL 启动修复](JLINK_DLL_STARTUP_FIX_20261022.md)。构建产物、升级包和运行日志不纳入 Git。已完成 92 项离线测试（指定主机候选核验目录）及 Windows 界面/蓝牙环境检查，实机升级和并发吞吐需另行验证。
