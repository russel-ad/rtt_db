# RTC 走时验证

使用主机 `V001-RTC1` 专用测试固件，打开 RTT 工具第五个标签页“RTC 验证”。已完成一块完整主机的烧录、对时和短时连续读时验证；24/72小时准确度、关机保时及温度对照尚未验收。

## 开始测试

1. 确认样机完整安装 BL5372 和外围电路。此前拆过 RTC 的低功耗诊断板不适合直接使用。
2. 安装匹配本机启动布局的 RTC1 固件。提供的升级包使用当前主机 NPL 布局，硬件标识 `DFT-SC20X-HUB`、计数3、APP地址 `0x409000`；不能把 raw APP 当作整片镜像下载，也不要直接用于旧布局设备。
3. 在“RTT / 串口调试”中配置已有连接，接收格式选择 ASC 或 UTF-8。RTC测试使用 `rtct` 命令，RTT使用通道0。开始前核对探针/串口对应的实际设备。
4. 对于关机保时测试，优先使用正常上电时可通信、关机时能物理断开的串口。SWD/RTT线和USB串口电平可能反向供电，正式关机期间应断开目标信号线，保持RTC所需电源连续。程序不会自动连接、复位、烧录或切换电源。
5. 点击“对时一次（电脑 UTC）”，确认收到成功回复。测试固件统一按 UTC 解释年月日，屏幕显示 UTC。一次对时本身存在秒级误差，后续通过基线相减扣除。
6. 填写板号或SN。先核对电脑时间；若已知参考时间来源和误差上限，可以记录来源并勾选“已核对电脑标准时间”。工具不自动修改电脑时间，也不自动测量或证明填写的参考精度。没有核验时仍可采集，但结果只表示相对电脑时钟的偏差。
7. 默认每60秒读取一次。需要自动判定时勾选产品指标并填写“秒/天”；初始输入框中的2秒/天只是示例，默认未启用，不是器件保证值或已经约定的产品标准。
8. 点击“开始采集”，选择报告保存位置。设备确认设时锁定后，首个有效读数建立基线。建议先24小时筛查，再72小时及7天观察。

漂移图横轴显示自首个有效读数起的测试时长，默认单位为“分钟”。长测可用图上方的“横轴单位”切换到“小时”。采集中也可切换，已绘制的点会按所选单位重绘，采样和报告里的原始秒数保持原值。

采集期间保持电脑运行，避免系统睡眠和主动修改时间；在结束时再次核对参考来源。电脑时钟发生可检测的跳变会使报告要求复核，渐进校时仍可能混入测得的RTC漂移。

## 关机保时测试

先点击“暂停 / 关机测试”，再正常长按主机电源键关机。断开可能反向供电的目标信号线，保留RTC设计要求的电源。等待24/72小时后正常开机并重新连接，再点“继续采集（重新锁定）”。不要再次对时。

继续时保留原电脑基线；新一次主机启动会被记录。若开机原始状态表明RTC曾停振、时间无效或重新写过时间，报告会要求复核。运行中意外重启而没有按流程重新锁定，也会留下异常证据。

暂停只暂停电脑轮询，不会清除RTC停振标志或改变RTC时间。保持程序打开，暂停跨关机时段继续使用同一测试记录。当前没有跨程序退出或电脑重启的续测功能；退出前停止并保留本轮报告，重新启动程序后另建测试。

## 数据和计算

每轮自动创建独立目录，逐笔刷新：

- `samples.csv`：UTC请求/回复时刻、通信往返时间、RTC原始秒数、寄存器、启动标识、读取失败/设时计数、锁状态及误差结果。
- `events.jsonl`：原始回复、基线、暂停/继续、超时、重启与结束事件。
- `report.json`：最新汇总、判定、待复核标记和测量限制。

累计漂移 = 本次RTC对参考时间的偏差 − 初始偏差；秒/天 = 累计漂移 ÷ 实际间隔秒数 ×86400；ppm = 累计漂移 ÷ 实际间隔秒数 ×1000000。正数表示RTC快，负数表示慢。

RTC只有整秒读数，工具将读数视为 `[秒值, 秒值+1)`，用请求/回复中点估算偏差。漂移误差界包含起止两次的秒量化、请求往返区间，以及填写的两端参考误差上限；界面的小数显示并不代表毫秒级RTC精度。

只有测试至少24小时、填写参考误差上限、启用产品指标且没有待复核异常时，才可给出相对声明参考源的PASS或FAIL。误差区间与指标边界重叠时是 `INCONCLUSIVE`；未核验参考源时只报告相对PC误差。各类结果均不能外推为所有板、所有温度或RTC规格验收。

“停止并保存”会请求释放设备设时锁，并等待确认。连接断开导致确认失败时，报告仍保存，同时标记锁状态未确认；重新连接后可点击“释放上次设时锁”。程序不会自动重设RTC。

## 主机测试固件行为

测试页显示RTC日期、时间、读取错误、写入次数、当前和开机原始XSTP、校准寄存器和最近一次电脑漂移批注及其年龄。没有电脑批注时显示 `--`。主机Tick只用于诊断和批注年龄，不是准确度基准。

测试包每秒读取RTC、禁用无人操作自动关机、由测试页独占普通UI。物理长按电源关机路径保持。它用于隔离验证RTC，不用于冲煮业务验收或整机低功耗测量；正常业务负载、充电和温度对照应另按相同参考方法组织验证。

启动时不写默认日期，不清除停振证据；明确对时后允许驱动按原有方式清XSTP。采集中所有已有设时和校准API均拒绝写入。采集锁和计数只存RAM，不周期写Flash；重启次数由电脑比较启动标识统计，并非芯片的永久累计次数。

测试结束恢复正式业务固件后，应按产品使用的时区重新对时。本测试写入RTC的是UTC。短时读时仅验证功能，走时准确度须按长测报告判断。
