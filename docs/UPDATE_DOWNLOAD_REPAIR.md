# 旧版上位机更新下载修复

适用场景：v2.10.0～v2.10.4 获取更新信息超时，下载中断，或修复工具提示 `CERTIFICATE_VERIFY_FAILED` / `unable to get local issuer certificate`。

1. 等设备任务结束后，退出原上位机。
2. 下载并完整解压 `RTTTool_UpdateRepair_2.10.5.zip`。保留解压目录中的 `_internal`，其中包含公共 CA 证书及运行组件。
3. 运行 `RTTTool_UpdateRepair.exe`，选择原上位机文件夹顶层的 `RTTTool.exe`。
4. 点击“下载并准备更新”。界面显示实时百分比、已下载/总大小及速度；网络中断会自动重试，保留下载进度供续传。
5. 准备完成后，点击“启动上位机”。原启动器安装新版并执行启动检查，成功后标题显示新版本。

修复工具使用内置正式更新地址及发布公钥，验证 Ed25519 签名、大小和 SHA256。它只准备更新包，版本安装和启动回退仍由原启动器完成，不连接蓝牙或操作设备固件。

v2.10.4 增加 GitHub API 清单入口，可直接读取仓库中同一份签名清单的 Base64 内容，避免再跳转到原始文件域名。清单响应读取中断也会重试；API 暂不可用时使用原发行入口。不同入口仍执行相同的签名、版本和摘要校验，测试频道沿用自己的显式地址。

v2.10.5 为更新连接增加 Windows 原生证书链验证及包内公共 CA，支持补全缺失的中间证书。
继续验证域名、有效期及可信签发者；程序不关闭证书校验，不向系统导入证书。

若仍报错，点击“HTTPS 诊断”。诊断只读取并验签正式清单，连接该签名所指向的安装包并读取
ZIP 前缀，不准备或安装更新。点击“复制诊断”提供结果，可看到失败域名、`verify_code`、
`verify_message`、证书后端和 CA 版本。诊断通过只代表这两个 HTTPS 入口通过检查，不代表
完整更新包已经下载或通过摘要校验。结果同时保存在更新目录 `last-https-check.json`。

若网络持续无法访问更新服务器，工具会保留部分文件。恢复联网后，再次点击“下载并准备更新”继续。
错误记录位于 `%LOCALAPPDATA%\RTTTool\updates\last-repair-error.json`；请仅提供此诊断文件中的错误文本，不发送账号缓存或工厂资料。

从 v2.10.3 起，上位机自带下载续传；v2.10.4 增加清单备用入口和读取重试，v2.10.5 增加原生证书链校验和公共 CA。后续正常使用程序内更新即可。
