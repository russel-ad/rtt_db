## 入口与操作

双击新版 `rtt_t2_ble_dfu.exe`，切换到“蓝牙 DFU 升级”页。原有“RTT / 串口调试”页保留。
Windows 10/11 x64，无需另装 Python 或 Nordic Dongle，使用电脑自身的 BLE 适配器。

1. 点击“检查蓝牙”确认本机适配器状态和名称，再点击“扫描设备”。扫描约 12 秒，列表旁显示本次接收和当前显示的数量。
2. 在列表选择从机，点击“连接并查询”。也可手工输入设备公共蓝牙地址。
3. 点击“选择固件”，选取现有原厂 OnMicro DFU ZIP；界面自动检查格式、ROM ID、长度及 CRC16。
4. 核对设备当前版本、固件目标版本和设备分区，然后点击“开始升级”。
5. 界面显示传输进度、速度、时间和操作日志。只有提交成功、设备重启、重连读到目标版本后，才显示“升级成功”。

使用前释放手机等其他中央设备对从机的连接，并让产品处于允许该电脑连接的状态。
本工具不更改设备的既有配对策略；不会自动清配对或执行恢复出厂设置。

设备名可能只在扫描响应中出现。电脑收到基础广播而未收到扫描响应时，旧版的 `SC200` 名称筛选会隐藏这类设备；修复版保留符合上述服务的未命名候选，也支持冒号、连字符或连续十六进制形式的 MAC 筛选。弱信号排查时先关闭 RSSI 过滤。基础广播也未收到时，列表仍不会凭历史记录或手机截图生成设备，需继续检查无线接收；扫描修复不代表已通过实机连接或升级。

## 分区、传输与取消

- 默认“旧设备首次升级”，限制最终 BIN 不超过 280 KiB。
- “已完成分区迁移”允许至多 400 KiB，仅用于已经确认完成分区迁移的设备。界面不会自动推断迁移状态。
- 本工程 400 KiB APP + 400 KiB 暂存布局至少需要 832 KiB Flash，512 KiB 不适用。实际硬件容量和 CFG/NVDS 边界需另外确认。
- 如设备已是目标版本，默认拒绝重装；确实需要时勾选“允许重装同版本”。
- 高级传输设置可选择自动分片或 20 字节兼容模式，调整 PRN（默认 8）、包间延时和地址类型。
- “取消操作”可停止扫描、连接或尚未提交的固件传输。本版本不实现跨断连续传，下一次从头开始。
- 最终提交至重启确认期间不接受取消，避免重复提交。最终回执丢失会显示结果未确认，应先重新查询设备版本。
- 传输进度达到 100% 仅表示数据传输完成，不能代替重启后的版本确认。
- 升级期间 RTT 日志仍可查看；会暂时禁用 RTT 页中硬件连接和发送按钮，避免复位或其他写操作打断升级。
- 已有资源发送任务正在运行时，不允许同时开始蓝牙升级。

## 日志与设置

DFU 日志单独保存到 `%LOCALAPPDATA%\RTT_T2\ble_dfu\logs`。
可以在界面点击“日志目录”定位，或点击“导出日志”另存为文件。
不会更改现有 RTT 日志格式及 `config.json` 的字段。

## 源码与构建

- `ble_dfu_panel.py`：图形界面及后台事件循环桥接。
- `onmicro_dfu/`：ZIP 校验、协议引擎、Windows BLE 适配和连接/升级控制器。
- `rtt_ble_launcher.py`：集成版 EXE 入口与不写设备的界面冒烟测试。
- `tests_ble_dfu/`：离线协议、控制器、UI 状态及原有 RTT 页集成检查。
- `build_ble_dfu.ps1`：生成新 EXE 到 `dist/ble_dfu/`，不覆盖原 `dist/rtt_t2.exe`。
- `build.bat` / `rtt_t2.spec`：原构建入口也已补充 BLE 依赖收集和单一 Qt 绑定配置。

源码运行使用主程序已有依赖，另需 `bleak==2.1.1`。PyQt5 为原有 UI 框架。

```powershell
python -m unittest discover -s tests_ble_dfu -v
.\build_ble_dfu.ps1
```

所有 BLE 对象由同一个后台 asyncio 事件循环持有，界面通过 Qt 排队信号更新，不在 GUI 线程等待蓝牙操作。
原厂 DFU 整份 BIN 作为一个数据对象，仅在完整接收并校验后执行一次最终提交。
