## v2.10.6：服务器登录与响应追踪号

后端响应外层可以携带可选的 `requestId`，兼容登录及 App 凭据等接口。追踪号仍限 null 或最多 256 字符的字符串，其他未知外层字段和凭据内容继续严格校验。

当前联调网关为 `http://192.168.1.167:20000`。在“账号与服务器”中确认地址，并勾选“允许局域网 HTTP（联调）”。新包只更新默认地址，电脑之前保存的地址会保留；如果仍是 `.162`，请手动修改。密码与网关绑定，更换地址后可能需要重新输入密码。

`HTTPS transport failed (1)` 是连接被拒绝，早于 JSON 字段校验。先确认新地址、端口和局域网可达；收到 HTTP 响应后，新增追踪字段才由本次兼容修改处理。

## v2.9.6：三至四台先认证，再并发传输

同时升级设为 3～4 台时，工作台依次完成本批设备的蓝牙连接、公开身份核对和 App 认证，表格先显示“App 已认证，等待本批设备连接完成”。本批准备结束后同时开始传输，之后各自重启并验版。超过并发数的设备按下一批处理，当前批次全部收尾后再连接下一批。

需要绑定的设备仍须打开本机窗口并明确确认；连接失败会记录该行的失败结果，其余准备成功的设备继续升级。100% 传输仍须等待“成功（已验版）”。RSSI 过滤选项继续使用。此构建的实际四台 240 秒验收另记现场报告，软件回归或开始传输不代表已经达标。

## v2.9.5：左侧蓝牙列表 RSSI 过滤

在“扫描／连接设备”下方增加“RSSI 过滤”开关和阈值，默认开启、阈值为 **≥ −60 dBm**。数值越接近 0，信号越强；例如 −49 dBm 显示，−65 dBm 隐藏。取消勾选可显示全部扫描结果。开关和阈值会保存，下次打开继续使用。

扫描过程中收到新信号值会立即更新显示，并显示“当前可见／扫描收到”的设备数。开启过滤时，没有有效 RSSI 的设备也会隐藏。隐藏设备会清除批量勾选，“勾选全部设备”只选择可见设备；单台连接和批量开始都检查可见性，避免按过滤前的位置操作另一台设备。连接或升级期间过滤控件暂时锁定。

便携包为 `sc201_workbench_portable_batch_ota_rssi_20261103.zip`，完整解压后运行文件夹内 EXE。此版本增加列表过滤，双台 205.77 秒的结果仍依赖已验收的设备端固件；3～4 台并发在 240 秒内完成尚待实测。

若单文件 EXE 在其他电脑提示 `Could not create temporary directory!`，使用免安装文件夹版 ZIP：完整解压后运行文件夹内的 EXE，保留 `_internal`。它无需在启动时向系统临时目录解压依赖，操作说明见 [PORTABLE_START.md](PORTABLE_START.md)。

在 RTT 工具的“SC201 设备工作台”标签页中使用原 `sc201_host` 的完整工作台。它是同一 Qt 应用内的原生控件，沿用来源工程的界面、通信、认证和业务实现。

v2.9.0 在“固件升级”增加多设备并发加密升级，默认同时 2 台，可设为 1～4 台。左侧勾选设备后按批次自动连接、认证、升级和验版，详见 [多设备升级说明](SC201_BATCH_OTA.md)。

## 资料与操作

首次打开该标签页时载入组件。顶部显示实际资料目录；在当前开发机优先沿用来源工程的 `private/workbench`，可通过“选择资料目录”指定原有资料。配置记在 RTT 的 `config.json` 中。原工作台的 SC201 设置标识保持一致。

相同资料目录使用原 `workbench-gui.lock`，不能与独立工作台同时打开。便携程序在来源目录不存在时使用本程序目录下的 `private/workbench`；需要原资料时明确选择原目录，程序不会自动复制或合并密钥台账。

工作台与旧 BLE DFU、出厂配对互斥使用蓝牙；切换前停止操作并断开设备。工作台连接、扫描或执行业务时，旧蓝牙入口和 RTT 发送/复位类控件会锁定。RTT 日志仍可查看。

关闭 RTT 时会检查工作台的实际状态。连接、业务或升级确认仍在进行时，先在工作台停止操作或等待完成，再关闭窗口。

独立的“蓝牙 DFU 升级”仍处理原厂 OnMicro DFU ZIP；工作台“固件升级”沿用 `sc201_host` 的加密 OTA 格式和校验，两者分别保留。

## 构建

```powershell
git -C E:/onm/sc201_host fetch origin
# 来源目录有本地修改时，创建独立工作树，不覆盖原工作区。
git -C E:/onm/sc201_host worktree add --detach G:/rtt_db/build/sc201_host_source 9dbd83bbdc712f2df773b7a74376eb41d4f49855
git -C G:/rtt_db/build/sc201_host_source submodule update --init
python -m sc201_workbench.build_native --source G:/rtt_db/build/sc201_host_source --dependency-source E:/onm/sc201_host --data-directory E:/onm/sc201_host/private/workbench --tests --upstream-tests
powershell -NoProfile -ExecutionPolicy Bypass -File ./build_ble_dfu.ps1 -Workbench -Suffix integrated
```

原生组件需要原工程配套的精确 libmlink、Mbed TLS、Qt 5.15.2 MSVC x64 SDK 和 VS C++ 工具链。构建脚本从依赖工程已有构建缓存解析 Qt 位置，也可传 `--qt-dir`；通过附加 CMake 目标复用来源源码，构建输出保存在 RTT 的 `build` 中。构建前后校验来源文件哈希和提交，提交与来源锁不匹配时拒绝构建，避免重新合入旧版本。来源工作区已经位于锁定提交时可直接传入它。

`--dependency-source` 只提供已有 Mbed TLS、OpenSSL、运行库及许可证缓存，不替代 `--source` 下的产品源码和 libmlink。`--data-directory` 指定默认资料位置，构建和离线测试不会读取或修改该目录的设备台账。`--tests` 和 `--upstream-tests` 构建测试程序，实际执行结果另行记录。

`sc201_workbench/native/build.json` 记录来源提交、实际源文件哈希和组件 SHA256。组件、HTTPS 和 VC 运行库随 RTT EXE 打包；交付不需要安装 Python，不带实机台账、账号凭据或固件。原工程既有内部工厂材料仍属于内部工具范围。

测试使用独立临时资料目录，不自动登录、扫描、连接、生产或升级设备。实机和服务器验收需要实际账号、设备及操作。

## 本轮验证范围

原 RTT/BLE Python 回归 80 项通过、16 项缺少旧固件夹具跳过，出厂配对 22 项通过，新工作台集成 8 项通过。源码及打包后的真实 Windows 界面均载入四个顶层标签页和原工作台五个功能页；清除开发机 Python/Qt PATH 后，EXE 仍能加载组件及随包 OpenSSL 1.1.1w。测试均使用独立资料目录。

补跑原工程六项 C++ 回归，GATT 状态、BLE 重试归属、OTA 目标界面和升级验版归属四项通过。原独立测试程序 `secure_workflow` 和 `bench_ui_workflow` 在并行离屏和 Windows 原生串行复测中均未通过；失败记录包含模拟端 JSON 回复队列忙（`rc=-10`）和流程等待超时。这两个程序不加载本集成 DLL；本轮未修改来源工程或公共库来绕过失败，不能将它们记为通过。

原始测试、构建、截图和 JSON 报告保存在 `build/sc201_workbench_integration_20261102/`。本轮没有实机登录、生产写入、认领或 OTA 验收。
